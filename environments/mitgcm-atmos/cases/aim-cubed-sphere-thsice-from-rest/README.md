# aim-cubed-sphere-thsice-from-rest

Upstream test: `code/mitgcm/verification/aim.5l_cs/input.thSI`. Policy: `pointwise`.

## The test

AIM v23 with pkg/thsice thermodynamic sea ice and slab ocean, spun up from rest. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/aim.5l_cs/input with the input.thSI overlay: the SPEEDY v23 physics on the 32x32x6 cubed sphere with 5 pressure levels, 6 tiles of 32x32 with exch2, but with a THIRD surface package stacked under AIM - pkg/thsice (useThSIce=.TRUE. with data.ice: Tf0kel=273.15, rhosw=1030., iceMaskMin=0.01, hThinIce=0.1, hiMax=hsMax=10., stepFwd_oceMxL=.TRUE. so the slab ocean mixed layer is stepped forward, tauRelax_MxL=5184000., stressReduction=0.) beside pkg/land and pkg/aim_v23, and with the coupled-model surface boundary fields (topo.cpl_FM.bin, landFrc.cpl_FM.bin, albedo_cs32.bin, seaSurfT/lndSurfT/seaIce/snowDepth/soilMoist .cpl_FM.bin) instead of the 2f2/FM set of the primary deck; the dynamics is again vector-invariant with useJamartWetPoints, staggerTimeStep, a nonlinear rStar free surface (nonlinFreeSurf=4, select_rStar=2, exactConserv, hFacInf=0.2, hFacSup=2.0, hFacMin=0.2, uniformLin_PhiSurf=.FALSE.), integr_GeoPot=2 with selectFindRoSurf=1 and atm_Rq=0.6078E-3, third-order humidity advection, cg2d on cg2dTargetResWunit=7.8E-16, and pkg/shap_filt with nShapT=4, nShapUV=4, nShapTrPhys=1, Shap_TrLength=140000., Shap_Trtau=5400., Shap_uvtau=1800.; unlike every other AIM check this deck starts FROM REST at nIter0=0 (no pickup: U=V=0, theta=tRef, specific humidity identically zero, surface pressure from the topography alone) and runs the deck's own 10 steps of 450 s (75 minutes), which is the full upstream window..

The production path it forces: pkg/aim_v23's aim_do_physics.F/phy_driver.F over 6144 columns each step (phy_shtorh.F, phy_convmf.F, phy_lscond.F, the SOL_OZ/RADSW shortwave and the four-band RADLW longwave of phy_radiat.F, the surface-flux chain phy_suflux_prep/land/ocean/sice/post.F with aim_splitSIOsFx separating the sea-ice and open-ocean fluxes, phy_vdifsc.F); pkg/thsice's thsice_step_temp.F, thsice_solve4temp.F and thsice_slab_ocean.F over every ocean column; pkg/land's implicit ground-temperature solve; and on the dynamics side mom_vecinv.F with the experiment's own mom_vi_hfacz_diss.F and mom_vi_mask_vort3.F, the rStar update, gad_advection for T and q, and shap_filt_uv_s2.F/shap_filt_tracer_s2.F over the exch2 halos..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 10, the graded
value; the upstream deck runs 10 steps of 450 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`, the input.thSI/ overlay),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `SOLC=342.0000000000001` in `data.aimphys` instead of 342:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

`run.sh altbuild` runs `ic/nominal` on an alternative build of the same source, `genmake2 -ieee` (gfortran -O0
-ffloat-store, strict IEEE arithmetic) instead of the optimised optfile; grading never uses it, self-validation measures the
check's floor between two legitimate builds from it.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The graded observable is the whole final dump (U, V, W, T, S, Eta, PH) plus the five time-averaged diagnostics streams that fall exactly on the end of the window, compared pointwise, and the reason the round-off bound is achievable here is much stronger than for the spun-up AIM decks: the run begins from an exactly uniform, motionless, completely DRY state (theta=tRef by level, specific humidity zero everywhere, no pickup), so over the first steps there is no convection to trigger (phy_convmf.F gates on a boundary-layer humidity threshold that a dry column never crosses), no large-scale condensation (phy_lscond.F gates on relative humidity above RHLSC), and no ice (thsice starts with iceMask=0 because startIceModel=0 with nIter0=0 and no thSIce*_InitFile takes the no-pickup branch of thsice_ini_vars.F). The switch-flipping argument that the other AIM checks have to make probabilistically is therefore nearly vacuous here for the first several steps: what the window measures is the radiative heating, the surface fluxes over land, ocean and the slab mixed layer, and the geostrophic adjustment of the atmosphere to real topography, all of which are smooth functions of the state. The remaining floors are ordinary: cg2d converges on cg2dTargetResWunit=7.8E-16 so an iteration-count difference perturbs Eta at about 1e-15, the rStar rescaling divides by column thicknesses bounded by hFacMin=0.2 over topography that is fixed, and the Shapiro filter is a fixed stencil with no limiter. The variant perturbs SOLC, the area-averaged solar constant of pkg/aim_v23 (package default 342. W/m2, set in phy_const.h by INPHYS before AIM_READPARMS reads the present-but-empty AIM_PAR_FOR group of data.aimphys); phy_driver.F passes it to SOL_OZ on every step and the top-of-atmosphere insolation FSOL is directly proportional to it, so the perturbation enters the shortwave heating of every daylit column on the very first step. A REVIEWER MUST KNOW WHY ABLWV1 WAS NOT USED HERE even though it is the variant of the sibling aim.5l_cs check: ABLWV1 enters RADLW only through TAU2 = EXP(-DELTAP*ABLWV1*QA), and QA (specific humidity) is identically zero at nIter0=0 in this deck, so a perturbation of ABLWV1 would have literally no effect on the first step and would only creep in from the lowest model level once surface evaporation has moistened it; SOLC has no such degeneracy.
Faults: This is the only check that reaches pkg/thsice's surface energy balance under an atmospheric model. Getting the ice/ocean flux split wrong in phy_suflux_post.F when aim_splitSIOsFx is on, or solving the ice surface temperature explicitly instead of by the Newton iteration of thsice_solve4temp.F, changes the surface sensible and latent fluxes by several W/m2 and the lowest-level T by parts in 1e-5 per step. Dropping the mixed-layer heat capacity term or the relaxation in thsice_slab_ocean.F changes the sea surface temperature by parts in 1e-6 per step, which the surface fluxes carry into T. On the atmospheric side the same faults as the primary AIM check apply: a dropped longwave band in RADLW, a cheapened mass-flux closure in phy_convmf.F, a fixed drag replacing the stability-corrected surface flux. Because this deck starts from rest and dry, the radiative and surface-flux faults dominate the window while the convective ones barely show - which is exactly complementary to the spun-up primary deck.

## Evidence

The overlay input.thSI carries its own data, data.aimphys, data.land, data.ice, data.pkg, data.shap and data.diagnostics, and its data sets nIter0=0, so the pickup.0000069120, pickup.0000069120.meta and pickup_land.0000069120 of the primary input/ directory are NOT read and are dropped (they would otherwise sit in the run directory as a trap; they cannot collide with the graded glob because the final iteration is 10, but a stray pickup invites a mis-glob). The six tile00N.mitgrid files and the FM/2f2 surface fields live in input/ itself, so links is empty and there is no prepare_run; the FM/2f2 .bin files are left in place but unused because input.thSI/data.aimphys and data.land name the .cpl_FM / .cpl / .mn variants instead - do NOT prune them by name-guessing. writeBinaryPrec is COMMENTED OUT in input.thSI/data (the upstream default is 32), so the generator's forced writeBinaryPrec=64 is load-bearing here; readBinaryPrec=64 is set and every input .bin is 64-bit. DIAGNOSTICS COINCIDENCE, LARGER THAN IN ANY OTHER CHECK: all five data.diagnostics streams have frequency 4500. and the window is exactly 10 x 450 s = 4500 s starting from t=0, so time-averaged surfDiag, dynDiag, aimDiag, aimDDT and thSIceDiag files ARE written at iteration 10 and will be collected and graded alongside the state. That is a genuine bonus (the AIM flux and tendency diagnostics are otherwise invisible to this module's checks) but it must be expected, and thSIceDiag will be all zeros or missing-value-filled if no ice forms in 75 minutes, which is deterministic and therefore harmless. The DIAG_STATIS_PARMS streams (dynStDiag, landStDiag, thSIceStDiag, with diagSt_regMaskFile='regMask_lat24.bin', which must be kept) write ASCII .txt files and are not matched by the .data glob. useMNC is commented out in data.pkg and packages.conf lists mnc, which genmake2 drops when no NetCDF library is found, so no extra edit. pkg/land's ground state, pkg/thsice's ice and mixed-layer state all live only in package pickups and are not directly graded. HONEST CAVEAT ON WHAT THIS CHECK ADDS: because the deck starts dry and ice-free, the thsice thermodynamics it nominally brings in is close to inert over 75 minutes; its real added value over aim-cubed-sphere-land is the from-rest, non-chaotic initial state, the aim_splitSIOsFx sea-ice/ocean flux split, the slab mixed layer, and a second, independent set of surface boundary fields.

Floor: self-validation measures it on every run from `run.sh altbuild`, the same source under genmake2 -ieee, graded against the nominal run with this check's validate.py, and records it in the rubric's evidence (floor, altbuild); that in-image number is the floor a reviewer reads. The native measurement of 2026-09-02 between the same two builds on the x86_64 host: the optimised gfortran build and the IEEE -O0 build differ on this deck by at most 9.5e-07 in absolute terms, 1.0e-02 of the bound (in dynDiag); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d W-unit target (the deck's active key; cg2dTargetResidual is inert here) loosened 1e10 to 7.8E-06 uses 8.6e+06 of the bound (FAIL, 496033 of 1474560 values over, cg2d 5 iterations instead of 16), and loosened only 1e3 to 7.8E-13 uses 2 of the bound (FAIL), and the variant parameter off by five percent 9.8e+09 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.3 s natively.
