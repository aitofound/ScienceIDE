# cheapaml-box-coare3

Upstream test: `code/mitgcm/verification/cheapAML_box/input`. Policy: `pointwise`.

## The test

A slab ocean under the cheap atmospheric mixed layer with COARE3 bulk fluxes. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/cheapAML_box/input: a 100x100 box on a spherical polar grid of 0.25 degree cells starting at 30N, decomposed into eight tiles of 50x25, with a SINGLE ocean level 1000 m thick over topog.box, so the ocean is a slab whose only job is to provide a sea-surface temperature; on top of it runs pkg/cheapaml, a two-dimensional atmospheric mixed layer of depth cheapaml_h=1000 m that carries its own air temperature and humidity, advects and diffuses them, and computes the air-sea fluxes itself with FluxFormula='COARE3', useRelativeWind=.TRUE. (so the stress is computed from the wind relative to the ocean current), useFreshWaterFlux=.TRUE. and useFluxLimit=.TRUE. (which selects the flux-limited third-order direct-space-time scheme, GAD_DST3FL_ADV_X/Y, for the atmospheric advection instead of centred second order), with cheapaml_ntim=5 atmospheric sub-steps per ocean step and a cheapaml_mask_width=4 relaxation frame at the lateral boundaries; the ocean itself is simple, viscAh=500, diffKhT=diffKhS=200, tempAdvScheme=33, staggerTimeStep, a linear equation of state and celsius2K=273.16, with PARM02 left entirely empty so cg2d runs on its defaults. The deck runs endTime=28800 s at deltaT=1200 s, 24 steps (eight hours); the window here is 48 steps, sixteen hours, twice the deck's own..

The production path it forces: pkg/cheapaml: cheapaml.F and cheapaml_timestep.F, which run cheapaml_ntim=5 sub-steps per model step, and above all cheapaml_coare3_flux.F, which for every one of the 10000 surface cells on every sub-step evaluates the COARE3 bulk algorithm with its Monin-Obukhov iteration (one or three passes of logarithms, powers and stability functions); this transcendental work, not the ocean, is what makes this the most expensive check per grid point in the module and it is the reason the estimated run time is the largest of the twenty added here despite the tiny 100x100x1 grid..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 48, the graded
value; the upstream deck runs 24 steps of 1200 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 2 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useMNC=.FALSE.` in `data.pkg`; `useDiagnostics=.FALSE.` in `data.pkg`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `cheapaml_h=1000.0000000000002` in `data.cheapaml` instead of 1000:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of U, V, W, T, S and Eta of the ocean plus the pkg/cheapaml state, U, V, W, T, S, Eta and the hydrostatic pressure, of the final dump under |c - r| <= 1e-10 + 1e-8|r|; pkg/cheapaml's own prognostic air temperature and humidity are NOT graded, because the package writes them only under its writeDbug flag and otherwise carries them solely in its pickup, which the generator suppresses by setting pChkptFreq=chkptFreq=0, so the atmosphere is tested only through the fluxes it imposes on the ocean, which is nevertheless a tight coupling because the ocean is a single slab whose temperature is driven by nothing else. The bound is physical because sixteen hours of a 0.25 degree box whose ocean is a single 1000 m slab is a smooth, diffusively controlled adjustment: the ocean barely moves, the atmospheric mixed layer relaxes towards equilibrium with it under a limited advection scheme, and there is no baroclinic instability, no convective adjustment, no freezing and no moving cell heights anywhere in the deck. The flux limiter selected by useFluxLimit is the ordinary Lipschitz-continuous DST3 limiter of pkg/generic_advdiff, built from min and max of continuous quantities, so it does not switch under a round-off perturbation. THE ONE GENUINE THRESHOLD IN THIS CHECK, and a reviewer must know about it, is inside COARE3: pkg/cheapaml/cheapaml_coare3_flux.F computes a first-guess Monin-Obukhov stability parameter zetu and then branches, 'IF (zetu .GT. 50.) nits=1 ELSE nits=3', choosing between one and three iterations of the flux algorithm. That is a discrete switch on a continuous quantity: a cell sitting within round-off of zetu=50 would take a different number of iterations in the nominal and the variant run and its fluxes would differ by a finite amount, not by round-off. zetu=50 is an extremely stable boundary layer, far outside anything a 30N to 55N ocean box with a modest air-sea temperature difference should produce, and the switch is evaluated 10000 times per sub-step and five sub-steps per step, so if it can fire it will fire early; that is why the window is only twice the deck's own rather than the four or five times used elsewhere. If the measured spread jumps, this is the mechanism, and the response is to shorten the window to the deck's 24 steps or to drop the check, not to loosen the bound. (The two other branches in the same routine, on Du greater than 10 and 18 m/s for the Charnock parameter, are continuous at their breakpoints, so they are kinks rather than jumps and are harmless.) The variant is cheapaml_h=1000, set explicitly in CHEAPAML_CONST of data.cheapaml, and it is the right probe because it is the parameter that defines this package: cheapaml_readparms.F sets hm=1/cheapaml_h and cheapaml_init_varia.F fills the cheapHgrid array with it, so it divides every atmospheric temperature and humidity tendency from the first sub-step of the first step and reaches the ocean through the fluxes immediately. It is achievable because the run is one process with the tiles swept in a fixed order (GLOBAL_SUM_ORDER_TILES), so every reduction and every solver sweep is deterministic and two correct builds of the same source differ only by round-off amplified through the steps of the integration; the nominal-versus-variant spread that selfcheck records is the measurement of that amplification under this exact rule, and the bound is finalised against it with the human.
Faults: Getting a COARE3 stability function or a transfer coefficient wrong changes the turbulent heat flux by tens of per cent over the whole box, which within sixteen hours changes the air temperature of a 1000 m mixed layer by tenths of a kelvin and the sea-surface temperature by a smaller but coherent amount. Dropping useRelativeWind and computing the stress from the absolute wind instead changes the momentum flux by the ratio of the current to the wind speed, per cent. Getting the cheapaml_ntim sub-stepping wrong, taking four sub-steps instead of five or applying the ocean tendency once per sub-step instead of once per step, changes the fluxes by tens of per cent. Dividing by the wrong mixed-layer depth (hm = 1/cheapaml_h in cheapaml_readparms.F) scales every atmospheric tendency. Single precision gives about 1e-7 relative.

## Evidence

useMNC MUST be forced off: data.pkg sets useMNC=.TRUE. and pkg/mnc is in code/packages.conf, but tools/genmake2 removes mnc from the build when NetCDF is absent, so ALLOW_MNC is not defined and packages_check would stop the run. useDiagnostics MUST also be forced off, and here it is not merely tidiness: data.diagnostics defines the cheapAML stream (CH_TAIR, CH_QAIR, CH_QNET, CH_EmP, CH_Uwind, CH_Vwind) at frequency(1)=14400., a POSITIVE frequency, i.e. a time-average every 14400 s, which at dt=1200 is every 12 steps and therefore lands exactly on iteration 48, the final iteration of the graded window; left on it would write cheapAML.0000000048.data into the glob the validator reads. PARM02 is EMPTY in this deck, so cg2dTargetResidual takes its default, 1.E-7 (model/src/set_defaults.F line 288), rather than a tight deck value; with a single level and a small box the free surface is nearly trivial, but this is by some way the loosest elliptic tolerance of any check in the module and it is the first thing to examine if the measured spread on Eta is large. DOUBT, FLAGGED FOR THE HUMAN: pkg/cheapaml is an atmospheric boundary-layer and air-sea-flux package, and the ocean in this deck is a single 1000 m slab with almost no dynamics, so a case can be made that this check belongs in the atmosphere module rather than in ocean dynamics; it is here because the module brief assigned it, and because the ocean side it does run (spherical polar metrics, flux-form momentum, the DST3 tracer scheme, staggerTimeStep) is the ocean core. If the module owner disagrees, this is the one of the twenty added checks to move. The deck uses endTime, so the generator must remove it and write nTimeSteps=48. readBinaryPrec=64 and topog.box (80000 bytes for 10000 points) is real*8. No pickup, nothing to link, nothing to gunzip; gendata.m is dropped. The native survey did not run this experiment: it is absent from native-walltimes.txt, so the runtime here is NOT a scaled measurement but an estimate built from the grid size, the tile count, the solver iteration counts printed in verification/cheapAML_box/results/output.txt and the step count of the window, calibrated against the decks the survey did time. Treat it as an order-of-magnitude figure. The digits are reproduced upstream: verification/cheapAML_box/results/output.txt exists and the run ends normally.

Floor: the optimised gfortran build and the IEEE -O0 build of the same source, run natively on the x86_64 host on 2026-09-02, differ on this deck by at most 2.5e-14 in absolute terms, 1.7e-04 of the bound (in PHL); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 1.6e+05 of the bound (FAIL), and the variant parameter off by five percent 3.3e+06 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 2.3 s natively.
