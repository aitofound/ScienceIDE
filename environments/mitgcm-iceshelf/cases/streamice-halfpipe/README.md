# streamice-halfpipe

Upstream test: `code/mitgcm/verification/halfpipe_streamice/input`. Policy: `pointwise`.

## The test

Half-pipe ice stream: the shallow-shelf velocity solve. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/halfpipe_streamice/input: an 80 km by 40 km Cartesian half-pipe ice stream on a 40x20 single-level grid (two 20x20 tiles, one process) with the ocean stepping switched off entirely (momStepping, tempStepping and saltStepping all false, Nr=1) so that the run is pure pkg/streamice; the shelf profile is built analytically from STREAMICEthickInit='PARAM' with shelf_max_draft=1300 m, shelf_min_draft=300 m, shelf_edge_pos=70 km and shelf_slope_scale=62 km, a uniform Glen coefficient B_glen_isothermal=700 and a uniform basal friction C_basal_fric_const=5 with n_glen=3 and n_basal_friction=1, a prescribed influx of 1.5e6 on the western face, a calving-front boundary condition on the eastern face, no-flow walls north and south, and STREAMICE_move_front=.TRUE. so the partially filled front cells evolve; the compile-time configuration in code/STREAMICE_OPTIONS.h selects the constructed matrix (STREAMICE_CONSTRUCT_MATRIX), the hybrid stress balance (STREAMICE_HYBRID_STRESS), the smoothed floatation taper (STREAMICE_SMOOTH_FLOATATION) and USE_ALT_RLOW, with PETSC undefined; every time step is 6307200 s (73 days) and the graded window is 20 steps, four years of ice-stream evolution and twice the deck's 10 steps..

The production path it forces: pkg/streamice/streamice_vel_solve.F, which runs a fixed 20 Picard iterations on the Glen's-law effective viscosity per time step, and inside each of them pkg/streamice/streamice_cg_wrapper.F and streamice_cg_solve.F, which build the driving stress and the block-structured stiffness matrix (streamice_cg_make_a, streamice_cg_adiag, streamice_cg_bound_vals) and then run roughly 85 to 120 diagonally preconditioned conjugate-gradient iterations to a relative residual of 1e-6, tightened by a factor 5e-2 whenever the outer residual has dropped a hundredfold; the viscosity and basal-drag update in streamice_visc_beta_hybrid.F and streamice_taub.F; streamice_driving_stress.F; and then streamice_advect_thickness.F with the flux-limited advection in streamice_adv_flux_fl_x.F and _y.F and the front update in streamice_adv_front.F and streamice_velmask_upd.F. That is roughly two thousand sparse matrix-vector products and four thousand global dot products per time step, which is why this is the acceleration check..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 20, the graded
value; the upstream deck runs 10 steps of 6.3072e+06 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 9 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `dumpAtLast=.TRUE.` in `data.diagnostics`; `frequency(1)=126144000.` in `data.diagnostics`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `B_glen_isothermal=700.0000000000002` in `data.streamice` instead of 700:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

`run.sh altbuild` runs `ic/nominal` on an alternative build of the same source, `genmake2 -ieee` (gfortran -O0
-ffloat-store, strict IEEE arithmetic) instead of the optimised optfile; grading never uses it, self-validation measures the
check's floor between two legitimate builds from it.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|; the fields `U`, `V`, `W`, `T`, `S`, `Eta`, `PH`, `PHL` are not graded.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is the land_ice diagnostics file, whose six fields are the surface velocity components, the ice thickness, the front mask, the floatation fraction and the surface elevation, averaged over the whole graded window; the ocean state dump is written but is frozen by construction (all three stepping switches are off) and is excluded from grading. The bound is physical because the shallow-shelf momentum balance is an elliptic problem with a unique solution once the Glen coefficient, the basal friction law and the boundary conditions are fixed: the velocity is not a free-running trajectory but the answer to a well-posed solve at every step, so a dropped viscosity term, a wrong strain-rate invariant, a cheaper solver or a truncated Picard loop moves it by parts in 1e-5 or more, far above a round-off bound. It is achievable, and this is the subtle part, because the nonlinear loop never converges within its iteration cap in this configuration: the upstream log shows err/err_init reaching only about 1.5e-3 after the first step's 20 iterations, well above streamice_nonlin_tol=1e-6, so the CONVERGED flag is never set and every step performs exactly 20 Picard iterations. That removes the worst reproducibility hazard an iterative solver has, a convergence test that a one-ulp perturbation could flip into a different iteration count; what remains is the inner conjugate-gradient stopping test, which does vary by an iteration or two between steps and could in principle differ between two correct runs, injecting a perturbation of order the current cg tolerance (1e-6 falling to 5e-8) at whichever Picard iteration it happens on. Perturbations injected early are contracted by the Picard iteration, which reduces the residual by roughly a factor 0.64 per sweep, but one injected at the last sweep is not damped at all, so the floor of this check is expected to be the loosest of the six and is genuinely unknown until it is measured; the probability of a flip is small because the residual would have to land within round-off of the threshold, but with about four hundred conjugate-gradient solves in the window it cannot be dismissed, and the measured nominal-versus-variant spread is what the bound must be set against. The window itself is not chaotic: four years of a laminar, viscosity-dominated ice stream with no feedback that could amplify a perturbation exponentially.
Faults: Stopping the Picard loop early, for instance at 5 iterations instead of streamice_max_nl_iter=20, leaves the residual a hundred times larger and moves the surface velocity by parts in 1e-2; the upstream log shows err/err_init still falling from 1.5e-3 towards 1e-4 at iteration 20, so the answer is genuinely a 20-iteration sequence and any shorter one is a different answer. Loosening streamice_cg_tol from 1e-6 to 1e-4, or disabling the STREAMICE_lower_cg_tol tightening, moves the velocity by parts in 1e-5. Dropping the cross term in the effective viscosity in streamice_visc_beta_hybrid.F, or evaluating eps_glen_min on the wrong strain-rate invariant, changes the viscosity by percents and the velocity likewise. Replacing the flux limiter in streamice_adv_flux_fl_x.F by plain upwinding smears the thickness front by parts in 1e-2 within a few steps, and it also changes when a front cell fills, which shows up as an order-one difference in SI_hmask. A wrong hybrid-stress vertical structure in the basal-drag partition moves SI_usurf by percents. Single precision in the conjugate-gradient dot products degrades the achievable residual to about 1e-4 and is fatal.

## Evidence

Hazards, and this check has the most of any in the module. (1) The graded content depends entirely on the land_ice diagnostics file. With momStepping, tempStepping and saltStepping all false the state dump written by write_state.F is a frozen copy of the initial condition and carries no information at all, so land_ice must be present at the final iteration or the check grades nothing; it should be named as a required field in the rubric the way UICE is in the sea-ice task. The deck's frequency(1)=63072000 s is exactly its own 10 steps, which is why the upstream run happens to write land_ice at its final iteration; a 20-step run needs frequency(1)=126144000 (a replacement of an existing key, so safe) and dumpAtLast=.TRUE. as a guard in case the step count is overridden at run time. If the step count is ever changed again, frequency(1) must be set to steps*6307200 or dumpAtLast must be working. (2) SI_hmask is an integer-valued front mask (0, 1, 2, 3) inside land_ice and therefore a discrete observable: if a partially filled front cell fills on a different step in the two runs, the time-averaged mask differs by about 1/steps and the check fails loudly. The margin is large, because a 73-day step moves a substantial fraction of a cell of ice area, so a one-ulp perturbation is nowhere near flipping the event; but it is the one place where this check could go non-pointwise, and it should be watched during calibration. Because not_graded works on file prefixes and SI_hmask is a record inside land_ice, it cannot be excluded on its own. (3) STREAMICE_move_front=.TRUE. over 20 steps advances the front twice as far as upstream; if the front reaches the eastern calving boundary the behaviour is bounded by the CFBC condition, but if the selfcheck spread looks wrong the first thing to try is dropping back to the deck's own 10 steps. (4) verification/halfpipe_streamice/build/genmake_local sets ALWAYS_USE_F90=1 plus Tapenade flags. For a forward gfortran build this is a no-op, because the linux_amd64_gfortran optfile sets FC and F90C to the same compiler and only the pgf77-family optfiles consult ALWAYS_USE_F90, but if the build ever fails on fixed-form parsing of pkg/streamice this file is the reason and it must be copied into the build directory. (5) packages.conf disables mom_common, mom_fluxform, mom_vecinv and generic_advdiff with a leading minus, so this check's executable is genuinely different from the other five and cannot share a build. (6) ALLOW_PETSC is undefined, so streamice_cg_solve.F, not the PETSc wrapper, is the code under test. (7) data.pkg has useMNC commented out, so no NetCDF edit is needed; data.streamice_geomSetup is an alternative parameter file for the STREAMICE_GEOM_FILE_SETUP build, which is undefined here, and tr_checklist is a testreport helper, so both are dropped. The .box boundary and geometry files other than topog.box are only read by that alternative deck (STREAMICEthickInit='PARAM' means h_init.box is not read) but are harmless to keep. (8) This checkout has no input.streamice_shelf or input.streamice_wc secondary decks; halfpipe_streamice contains only input, input_ad and input_tap, so the ice-stream side of the module has exactly one forward deck.

Floor: self-validation measures it on every run from `run.sh altbuild`, the same source under genmake2 -ieee, graded against the nominal run with this check's validate.py, and records it in the rubric's evidence (floor, altbuild); that in-image number is the floor a reviewer reads. The native measurement of 2026-09-02 between the same two builds on the x86_64 host: the optimised gfortran build and the IEEE -O0 build are bit-identical on this deck over all 4800 graded values (floor 0.0, in no field; re-verified on 2026-09-04 with validate.py from the retained runs); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 0.0e+00 of the bound (NO EFFECT (no cg2d in this configuration)), and the variant parameter off by five percent 5.1e+08 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 8.5 s natively.
