# 写手简报 — edkit-adaptive-krylov-time-evolution

模块:Adaptive Krylov Time Evolution

**可变异的源文件(1 个,模块只编译这些)**
  src/algorithms/TimeEvolution.jl

**死代码 / 不可达(3 条,永远不要在这里出题)**
  - Operator local-term kernels, matrix-free multiplication, and symmetry-basis indexing; these are shared dependencies and a possible separate backend task.
  - Lindblad and Arnoldi open-system evolution; only the pinned pure-Hamiltonian integration path is used as cross-subsystem evidence.
  - Legacy Taylor propagation, tensor-network and TEBD evolution, entanglement analysis, inverse methods, and spectral workflows; these solve different scientific problems.

**坑(8 条)**
  ! The current Krylov cache allocates CPU Vector and Matrix storage and is not a general GPU-native implementation.
  ! EDKit Operator.mul! has accumulating semantics and is single-threaded on this path; output clearing is required, and porting the Krylov layer alone does not accelerate the matrix-free Operator backend.
  ! Hermiticity is assumed rather than checked, backward time is unsupported, and the cache has mutable forward-only state.
  ! The defect-monitor tolerance is not a proven global state-error bound; adaptive sampling is capped and lucky breakdown uses a separate floating-point threshold.
  ! The reuse_basis keyword is stored but has no observed execution effect at this pin and cannot serve as a trusted baseline control.
  ! The pinned Manifest was generated by Julia 1.12.5 and was incompatible with the declared Julia 1.10 runtime during the native survey; a clean external Julia 1.10 resolve was required without changing source.
  ! Several official documentation examples use unseeded random initial states; deterministic task fixtures must record the added seed.
  ! Existing upstream tests use normalized nonzero initial states and leave a norm-restoration and normalize_output coverage gap.
