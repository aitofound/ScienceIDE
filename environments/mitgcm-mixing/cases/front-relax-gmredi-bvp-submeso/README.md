# front-relax-gmredi-bvp-submeso

Upstream test: `code/mitgcm/verification/front_relax/input.bvp`. Policy: `pointwise`.

## The test

GM boundary-value-problem streamfunction with the sub-mesoscale parameterisation. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/front_relax with the input.bvp overlay, which shares the initial fields of input.mxl through a prepare_run symbolic link: the same 1x32x25 y-z channel with a 200 m mixed layer over a stratified warm bowl at 100 km horizontal resolution, but with the sloping bottom topo_slp.bin instead of the flat topog.bin, and with pkg/gmredi in its advective form, GM_AdvForm=.TRUE., using the boundary-value-problem eddy streamfunction, GM_useBVP=.TRUE. with GM_BVP_modeNumber=5, so that the bolus streamfunction is obtained by solving a vertical boundary-value problem with a five-mode wave speed instead of being read off the slope, together with the sub-mesoscale mixed-layer eddy parameterisation, GM_useSubMeso=.TRUE. with subMeso_Ceff=3e-2, the same GM_background_K=1000 for the GM and Redi coefficients, the linear taper at GM_maxSlope=1e-2 and GM_facTrL2dz=0; cAdjFreq=-1 makes convective adjustment run every step, no_slip_bottom with linear bottom drag is on, and the vertical diffusivity is again 1e-2 in the top six levels and 2e-5 below; the window is 24 steps of 3600 s, one day, one step less than the upstream 25. The overlay's two -86400 s snapshot streams, surfDiag (GM_BVPcW, GM_BVPcS, SubMesLf, SubMpsiY) and oceDiag (the four tensor components and the bolus streamfunction), are not graded: pkg/diagnostics/diagnostics_write.F evaluates a negative-frequency (snapshot) stream at myTime - deltaTClock and writes it during the following step under the previous iteration's suffix: measured natively on 2026-09-05, a 25-step run writes surfDiag.0000000024 while the final state dump carries iteration 25 (retained under comment/fault-probes), so no window makes a snapshot land on the final iteration and the snapshot streams are not graded; the check grades the state dump alone, and both closures are seen through the tracers and velocities they move..

The production path it forces: pkg/gmredi/gmredi_calc_psi_bvp.F, which solves the vertical boundary-value problem for the eddy streamfunction with five modes at every water column, feeding pkg/gmredi/gmredi_calc_tensor.F and gmredi_calc_psi_bolus.F, plus pkg/gmredi/submeso_calc_psi.F, which forms the sub-mesoscale mixed-layer streamfunction from the horizontal buoyancy gradient and the mixed-layer depth; the transports are applied through gmredi_xtransport.F, gmredi_ytransport.F and gmredi_rtransport.F inside model/src/calc_gt.F and calc_gs.F, and model/src/convective_adjustment.F runs its sweep every step..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 24, the graded
value; the upstream deck runs 25 steps of 3600 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`, the input.bvp/ overlay, and the files its prepare_run links from sibling experiments),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useSingleCpuIO=.TRUE.` in `data`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `GM_background_K=1000.0000000000002` in `data.gmredi` instead of 1000:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

`run.sh altbuild` runs `ic/nominal` on an alternative build of the same source, `genmake2 -ieee` (gfortran -O0
-ffloat-store, strict IEEE arithmetic) instead of the optimised optfile; grading never uses it, self-validation measures the
check's floor between two legitimate builds from it.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of the final state dump plus the two snapshot diagnostics files that close on the final iteration, compared relatively with an absolute floor. The bound is physical because with no forcing the one-day evolution is a deterministic functional of the two streamfunctions and the Redi tensor, and every fault above moves it by parts in a hundred or worse. It is achievable because the deterministic parts of the step are clean: the barotropic solve is set to cg2dTargetResidual=1e-13 on a 32-point domain, the flow has no x structure so baroclinic instability cannot grow, and the boundary-value problem itself is a direct tridiagonal solve over a fixed number of modes rather than an iteration with a tolerance, so it reproduces bit for bit between two runs of the same build. The one hazard this family of decks carries, and the reason the earlier survey wanted to exclude them, is cAdjFreq=-1: model/src/convective_adjustment.F runs every step and model/src/convective_weights.F decides cell by cell, on the strict sign test (rho(k)-rho(k-1))*rkSign*gravitySign < 0, whether to replace two adjacent cells by their volume-weighted mean. That is a discrete switch, but in this configuration its effect is very nearly continuous, and that is what makes the check defensible. Salinity is a passive dye with sBeta=0, so density is a function of temperature alone; the switch therefore fires exactly when the temperature difference across the interface changes sign, and at that moment mixing the two cells changes their temperature by half of a difference that is itself zero, so the temperature tendency is continuous across the switch. The only quantity that could jump is salinity, whose vertical gradient is not tied to the criterion; but the initial salinity field of this experiment is exactly uniform in the vertical (it varies with y only), so at the start mixing salinity is an exact no-operation, and the vertical salinity gradients that develop later are small. A perturbed run can therefore flip a marginal interface and the resulting difference is bounded by the local tracer jump rather than by anything O(1). This is an argument, not a measurement, and it is why the window is kept at or below the deck's own step count and why a native scan of the worst relative spread against window length at 6, 12, 24, 48 and 96 steps must be run before the bound is fixed: smooth growth means the window can stay or grow, isolated cells with O(1) differences mean the convective switch is flipping on a real salinity jump and the window must be shortened and the check flagged chaotic. A second, smaller caution is the sub-mesoscale length scale: pkg/gmredi/submeso_calc_psi.F builds it with MAX and MIN limiters against subMeso_LfMin and subMeso_Lmax, and a clamped column is insensitive to subMeso_Ceff, which is why the variant perturbs GM_background_K, the coefficient that acts in every wet cell of both tracers from the first step and that the deck writes explicitly, rather than the sub-mesoscale coefficient; subMeso_Ceff=3e-2 remains the natural second choice if a reviewer wants the perturbation to enter through the sub-mesoscale path specifically.
The binding field is S: the two-ulp variant uses 0.082 of the bound there (12x headroom, the same at 24 and at 25 steps in the native scan of 2026-09-05) and the two builds are bit-identical; the human accepted this headroom on 2026-09-05.
Faults: Two independent closures are on trial here, and both are seen through the graded state, since the diagnostics that would isolate them are not graded. Solving the boundary-value problem with the wrong mode number, or short-circuiting it to the plain slope-based streamfunction, changes the vertical structure of the bolus transport by tens of percent through most of the column, and the advected salinity, a passive dye moved only by that transport, by parts in 1e-2 within a day. Dropping the sub-mesoscale term altogether removes the restratifying flux inside the 200 m mixed layer, and the temperature field in the top ten levels differs by parts in 1e-2 within a day. A ten percent error in subMeso_Ceff or in the mixed-layer front length scale SubMesLf changes that flux by ten percent, parts in 1e-3 of T. A ten percent error in GM_background_K changes the interior slumping rate by ten percent. Because salinity is a passive dye moved only by the eddy transport and the Redi tensor, a fault in either shows in S at parts in 1e-2 with much less signal in T. A single-precision streamfunction leaves relative errors near 1e-7 in both tracers.

## Evidence

This is the only deck in the module that needs a prepare_run step: input.bvp contains no binaries at all and its prepare_run script symlinks every *.bin from input.mxl, so the generator must copy t_ini.bin, s_ini.bin, u_ini.bin, topo_slp.bin and topog.bin from verification/front_relax/input.mxl (topog.bin is linked by the script but not read here, since this deck's bathyFile is topo_slp.bin). prepare_run itself is dropped. The overlay supplies data, data.pkg, data.gmredi and data.diagnostics; input/eedata is used unchanged; the primary deck's Z-coordinate binaries, dy.bin (this deck sets delY explicitly), the matlab generator, data.mpi and eedata.mth are dropped. No MNC, no pickup, no cg3d. Of the four diagnostics streams, stream 1 (surfDiag) and stream 3 (oceDiag) are at -86400 s and fire exactly at 24 steps; stream 2 (dynDiag) at -864000 s and stream 4, which has no fileName at all, at 1728000 s stay silent, which is a reason not to lengthen the window past 240 steps without first checking how pkg/diagnostics handles a blank stream name. hMixCriteria=-0.1 selects the interpolated density-difference mixed-layer depth of model/src/calc_oce_mxlayer.F, which is a continuous function of the state; MXLDEPTH is graded. All binaries are real*8 and the deck sets readBinaryPrec=64 and writeBinaryPrec=64. This deck sets neither globalFiles nor useSingleCpuIO, so MITgcm's mdsio writes one file per tile and names the final dump <field>.<iteration>.001.001.data (pkg/mdsio/mdsio_write_field.F, the 'Case of 1 file per tile' branch), which the generator's collector and validate.py, both of which match ^<field>.<10 digits>.data$, would not see at all; the extra edit useSingleCpuIO=.TRUE. makes mdsio gather the tiles and write one global file per field, exactly as every sea-ice check's deck does. It is a pure I/O switch and changes no arithmetic; globalFiles=.TRUE. would do the same job for the non-exch2 decks, but useSingleCpuIO is the variant the finished task already exercises.

Floor: self-validation measures it on every run from `run.sh altbuild`, the same source under genmake2 -ieee, graded against the nominal run with this check's validate.py, and records it in the rubric's evidence (floor, altbuild); that in-image number is the floor a reviewer reads. The native measurement of 2026-09-02 between the same two builds on the x86_64 host: the optimised gfortran build and the IEEE -O0 build differ on this deck by at most 0.0e+00 in absolute terms, 0.0e+00 of the bound (in no field); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 5.4e+06 of the bound (FAIL), and the variant parameter off by five percent 1.4e+05 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.1 s natively.
