# mladjust-leith-biharmonic

Upstream test: `code/mitgcm/verification/MLAdjust/input`. Policy: `pointwise`.

## The test

Biharmonic Leith and Smagorinsky viscosity on vorticity and divergence. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/MLAdjust: a 50x26x40 zonally re-entrant channel closed by a wall at the northern edge (four tiles of 25x13 under pkg/exch2, uniform 1 km horizontal spacing and forty uniform 5 m levels, 52000 cells and the largest grid in this module's suite), started from a mixed-layer density front given by thetaInitial.bin with salinity carried as a passive spice tracer (spiceInitial.bin, sBeta=0) and a flat bottom from topo_sl.bin, with no forcing of any kind, f-plane at f0=7.29e-5, a linear equation of state, third-order direct-space-time flux-limited advection for both tracers, vertical viscosity viscAr=5e-5, ivdc_kappa=10 with implicit diffusion for convection, useJamartWetPoints, stagger time stepping, an implicit free surface with cg2dTargetResidual=1e-11 and no explicit horizontal background viscosity at all, so that the entire lateral momentum mixing is whatever the flow-dependent closure returns; the base deck runs vector-invariant momentum (vectorInvariantMomentum=.TRUE.) with the vorticity and divergence formulation of the viscous terms, free-slip sides and bottom, and a purely biharmonic flow-dependent viscosity: the full Leith scheme (useFullLeith=.TRUE.) with viscC4leith=1.85 acting on the gradient of the relative vorticity and viscC4leithD=1.85 acting on the gradient of the horizontal divergence, plus a biharmonic Smagorinsky term at viscC4smag=1, the whole capped by the grid- and time-step-scaled limiter viscA4GridMax=1, with no constant background viscA4 at all, so the biharmonic viscosity in every cell is entirely what the closure returns; the window is 12 steps of 1200 s, four hours, the upstream window and a small fraction of the ten-day endTime the base deck records as its production option; it was 6 steps until the measurement given in the warrant showed the two-ulp variant leaving every state field bit-identical there..

The production path it forces: pkg/mom_common/mom_calc_visc.F, which forms the Leith, Leith-divergence and Smagorinsky contributions on both vorticity and divergence points and applies the grid-scaled maximum, and the vector-invariant momentum routines of pkg/mom_vecinv (mom_vi_hdissip.F and the vorticity and divergence term routines) that use them, with model/src/calc_ivdc.F and model/src/impldiff.F handling the convective and implicit vertical parts and the third-order flux-limited advection of model/src/gad_dst3fl.F carrying the two tracers..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 12, the graded
value; the upstream deck runs 12 steps of 1200 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useMNC=.FALSE.` in `data.pkg`; `useSingleCpuIO=.TRUE.` in `data`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `viscC4leith=1.8500000000000005` in `data` instead of 1.85:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

`run.sh altbuild` runs `ic/nominal` on an alternative build of the same source, `genmake2 -ieee` (gfortran -O0
-ffloat-store, strict IEEE arithmetic) instead of the optimised optfile; grading never uses it, self-validation measures the
check's floor between two legitimate builds from it.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of the final state dump (U, V, W, T, S, Eta, PH, PHL) plus the momDiag and viscDiag files that dumpAtLast writes at the final iteration, graded relatively with an absolute floor. The bound is physical because the coefficient under test is not a tuned constant but a formula evaluated from the resolved vorticity and divergence gradients: it has one right answer per cell per step and every fault above displaces it by parts in a hundred or worse, many orders of magnitude above the round-off floor. It is achievable at a short window because the only tolerance-bearing step is the barotropic solve, and the deck sets cg2dTargetResidual=1e-11, tight enough that the residual falls well past the threshold in a fixed number of iterations and the solve contributes no realistic iteration-count sensitivity; everything else in the step, the viscosity formulas, the advection with its continuous flux limiter and the implicit vertical solves, is fixed-length direct arithmetic with no convergence test, and the run is a single process with a deterministic tile sweep, so two runs of the same build agree bit for bit and the whole measured spread is the amplification of the deliberate two-ulp change. Two hours is also short compared with the days it takes a 1 km front on an f-plane at f0=7.29e-5 to roll up into eddies, so the comparison is made on a laminar adjusting front rather than on a turbulent field, which is what keeps a pointwise rule honest. The measured behaviour of this experiment is the governing fact for this check. A native window scan on the x86_64 host on 2026-09-02, using the sibling deck input.QGLthGM and a one-ulp variant of viscC2LeithQG, found the worst relative spread in salinity growing steadily and smoothly with the window: 7.5e-10 at 6 steps, 7.8e-9 at 12, 1.4e-8 at 24, 4.7e-8 at 36 and 9.5e-8 at 48. That is continuous amplification, not a threshold flipping, and it has two sources that every MLAdjust deck shares. The first is the closure itself: the viscosity is a function of the flow gradients and the viscosity in turn sets the flow gradients, so a perturbation feeds back on itself every step through pkg/mom_common/mom_calc_visc.F. The second is the spice tracer: salinity is stepped with sBeta=0, so it carries a finite vertical gradient across interfaces where the temperature gradient, and hence the density gradient, is neutral, and the strict sign test of model/src/calc_ivdc.F can flip such an interface between a vertical diffusivity of 1e-5 and 10 m2/s while the temperature flux stays negligible. That is why salinity, not temperature, carries the largest spread. The same two mechanisms are present in this deck with the same grid, the same initial front, the same ivdc_kappa and the same class of flow-dependent viscosity, so the same amplification must be expected until it is measured here, and the check is graded over 6 steps, two hours, half the upstream twelve-step window, where the sibling's spread sat thirteen times inside the rule, and is flagged chaotic. That scan was run on 2026-09-05 (below) and the window was lengthened to the upstream twelve on its result.
Measured on 2026-09-05 from the retained runs: at 6 steps the two-ulp viscC4leith variant left Eta, PH, PHL, S, T, U, V, W and momDiag bit-identical and moved viscDiag alone, by 7.6e-8 of the bound; at 12 steps U and V move by 8.4e-9 and 1.0e-9 of the bound, momDiag by 2.7e-13 and viscDiag by 8.6e-8, so the window is the upstream twelve and the variant reaches the state, faintly; the check's discrimination rests on viscDiag, the viscosity the closure returns, where both fault probes land more than 1e7 over.
Faults: Because there is no background biharmonic viscosity, the entire lateral dissipation is whatever mom_calc_visc.F returns, so a fault there cannot be masked. Getting the power of the grid spacing wrong in the biharmonic Leith coefficient (it enters as the fifth power of the grid scale divided by pi) changes the viscosity by an order of magnitude and the graded VA4DLTH and VA4ZLTH fields by O(1). Using only the vorticity gradient and dropping the divergence part, that is ignoring viscC4leithD, leaves the divergent modes undamped and changes momHDiv by parts in 1e-1 within two hours. Applying the viscA4GridMax cap to the sum instead of to each contribution, or before instead of after the Smagorinsky term, changes only the strongly strained cells but by a factor of order one there. Evaluating the closure on vorticity points with the tracer-point metric terms, a classic error on a C grid, changes VISCA4Z by tens of percent. Single-precision viscosity leaves around 1e-7 relative in the velocity field.

## Evidence

This is the base deck of the experiment, run straight from input/ with no overlay. It uses input/data, input/data.pkg, input/data.diagnostics, input/data.mnc, input/eedata and the three binaries. data.pkg sets useMNC=.TRUE. and must be turned off (no NetCDF in the image); data.mnc is then unread and is kept only so the deck stays recognisable. The initial fields thetaInitial.bin, spiceInitial.bin and topo_sl.bin (all real*8, 50x26x40x8 and 50x26x8 bytes) and data.diagnostics come from input/. That data.diagnostics sets dumpAtLast=.TRUE., so momDiag (momKE, momHDiv, momVort3, Strain, Tension, Stretch) and viscDiag (twenty-six viscosity fields: the harmonic and biharmonic viscosities on divergence and vorticity points and their maximum, minimum, Leith, Leith-divergence, QG-Leith and Smagorinsky contributions) are written to the run directory at the final iteration and are graded; their nominal frequency of 864000 s is 720 steps and never fires inside the window, so these are partial-window averages, which is deterministic and fine. The per-level statistics stream at stat_freq=7200 s writes plain text with diagSt_mnc=.FALSE. and is not collected. There is no diagMdsDir, so no directory has to be created. pkg/flt is compiled into packages.conf but useFLT is not set, and pkg/exch2 is compiled and builds its default topology from SIZE.h with no data.exch2, exactly as upstream. cg3dMaxIters and cg3dTargetResidual are set in the deck but nonHydrostatic is not, so cg3d never runs. eedata sets nTx=nTy=1. readBinaryPrec and writeBinaryPrec are both 64. This deck sets neither globalFiles nor useSingleCpuIO, so MITgcm's mdsio writes one file per tile and names the final dump <field>.<iteration>.001.001.data (pkg/mdsio/mdsio_write_field.F, the 'Case of 1 file per tile' branch), which the generator's collector and validate.py, both of which match ^<field>.<10 digits>.data$, would not see at all; the extra edit useSingleCpuIO=.TRUE. makes mdsio gather the tiles and write one global file per field, exactly as every sea-ice check's deck does. It is a pure I/O switch and changes no arithmetic; globalFiles=.TRUE. would do the same job for the non-exch2 decks, but useSingleCpuIO is the variant the finished task already exercises.

Floor: self-validation measures it on every run from `run.sh altbuild`, the same source under genmake2 -ieee, graded against the nominal run with this check's validate.py, and records it in the rubric's evidence (floor, altbuild); that in-image number is the floor a reviewer reads. The native measurement of 2026-09-02 between the same two builds on the x86_64 host: the optimised gfortran build and the IEEE -O0 build differ on this deck by at most 2.2e-11 in absolute terms, 5.6e-08 of the bound (in viscDiag); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 1.5e+07 of the bound (FAIL), and the variant parameter off by five percent 1.4e+07 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.4 s natively.
