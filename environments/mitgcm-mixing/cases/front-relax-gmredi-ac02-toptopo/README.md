# front-relax-gmredi-ac02-toptopo

Upstream test: `code/mitgcm/verification/front_relax/input.top`. Policy: `pointwise`.

## The test

GM advective form with the ac02 taper under a depressed model top. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/front_relax with the input.top overlay: a 1x32x25 y-z channel at 100 km resolution reaching 2.5 km depth over a sloping bottom (topo_slp.bin), and, uniquely in this module, a model top depressed by 50 m near the centre of the channel through topoFile='top_bump.bin', as it would be under a floating ice shelf, so that the surface cells are partial cells and the free surface is not flat; the mixed layer is only 60 m thick and very weakly stratified (the initial temperature differs by about 1e-8 K between the top three levels, a buoyancy frequency of order 1e-6 per second), salinity is again a passive dye with sBeta=0 and varies only with y, there is no surface forcing, f0=1e-4, viscA4=12e5, linear bottom drag with no_slip_bottom, diffKrT=diffKrS=2e-5 uniformly and cAdjFreq=-1 so convective adjustment runs every step; pkg/gmredi runs in its advective form, GM_AdvForm=.TRUE., with GM_background_K=1000, GM_maxSlope=1e-2 and GM_taper_scheme='ac02', the Aiki et al. taper that no other deck in the module selects (GM_useBVP is commented out here, so the five-mode boundary-value problem is not used even though GM_BVP_modeNumber is left at 5); hMixCriteria=1.5 selects the second, stratification-ratio mixed-layer criterion of model/src/calc_oce_mxlayer.F; the window is 24 steps of 3600 s, one day, one step less than the upstream 25. The overlay's two -86400 s snapshot streams, surfDiag and oceDiag, are not graded: pkg/diagnostics/diagnostics_write.F evaluates a negative-frequency (snapshot) stream at myTime - deltaTClock and writes it during the following step under the previous iteration's suffix: measured natively on 2026-09-05, a 25-step run writes surfDiag.0000000024 while the final state dump carries iteration 25 (retained under comment/fault-probes), so no window makes a snapshot land on the final iteration and the snapshot streams are not graded; the check grades the state dump alone..

The production path it forces: pkg/gmredi/gmredi_calc_tensor.F with the ac02 branch of pkg/gmredi/gmredi_slope_limit.F and gmredi_slope_psi.F, the bolus streamfunction of pkg/gmredi/gmredi_calc_psi_bolus.F and the transports of gmredi_xtransport.F, gmredi_ytransport.F and gmredi_rtransport.F inside model/src/calc_gt.F and calc_gs.F; the depressed top makes the surface hFac non-trivial, so the partial-cell arithmetic of model/src/calc_gw.F and the free-surface solve carry more weight here than in the other front_relax decks, and model/src/convective_adjustment.F runs every step..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 24, the graded
value; the upstream deck runs 25 steps of 3600 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`, the input.top/ overlay),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useSingleCpuIO=.TRUE.` in `data`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `GM_background_K=1000.0000000000002` in `data.gmredi` instead of 1000:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

`run.sh altbuild` runs `ic/nominal` on an alternative build of the same source, `genmake2 -ieee` (gfortran -O0
-ffloat-store, strict IEEE arithmetic) instead of the optimised optfile; grading never uses it, self-validation measures the
check's floor between two legitimate builds from it.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of the final state dump plus the two snapshot diagnostics files that close on the final iteration, graded relatively with an absolute floor for the near-zero cells. The bound is physical because with no forcing and no resolved eddies the one-day evolution is a deterministic functional of the tensor, the taper and the partial-cell geometry, and every fault above displaces it by parts in a hundred or worse. It is achievable because the deterministic parts of the step are clean: cg2dTargetResidual=1e-13 on a 32-point domain leaves no realistic iteration-count sensitivity, the flow has no x structure so baroclinic instability cannot develop, and the tensor and the tridiagonal solves are fixed-length direct arithmetic. The one hazard this family of decks carries, and the reason the earlier survey wanted to exclude them, is cAdjFreq=-1: model/src/convective_adjustment.F runs every step and model/src/convective_weights.F decides cell by cell, on the strict sign test (rho(k)-rho(k-1))*rkSign*gravitySign < 0, whether to replace two adjacent cells by their volume-weighted mean. That is a discrete switch, but in this configuration its effect is very nearly continuous, and that is what makes the check defensible. Salinity is a passive dye with sBeta=0, so density is a function of temperature alone; the switch therefore fires exactly when the temperature difference across the interface changes sign, and at that moment mixing the two cells changes their temperature by half of a difference that is itself zero, so the temperature tendency is continuous across the switch. The only quantity that could jump is salinity, whose vertical gradient is not tied to the criterion; but the initial salinity field of this experiment is exactly uniform in the vertical (it varies with y only), so at the start mixing salinity is an exact no-operation, and the vertical salinity gradients that develop later are small. A perturbed run can therefore flip a marginal interface and the resulting difference is bounded by the local tracer jump rather than by anything O(1). This is an argument, not a measurement, and it is why the window is kept at or below the deck's own step count and why a native scan of the worst relative spread against window length at 6, 12, 24, 48 and 96 steps must be run before the bound is fixed: smooth growth means the window can stay or grow, isolated cells with O(1) differences mean the convective switch is flipping on a real salinity jump and the window must be shortened and the check flagged chaotic. This deck deserves the caution more than its two siblings, because its mixed layer is not exactly neutral but only very nearly so: the initial temperature difference across the top interfaces is about 1e-8 K, so those interfaces are genuinely stable at the start and no convection occurs, but the margin against the sign test is only eight decades rather than the sixteen that separate a two-ulp perturbation from the mean state, and it is the smallest margin anywhere in this module. A scan of the worst relative spread against window length is therefore mandatory before the bound is fixed, and if it shows isolated cells with O(1) differences the window should be cut to twelve or six steps and the check flagged chaotic. The variant perturbs GM_background_K, which the deck writes explicitly and which sets both the GM and the Redi coefficient in every wet cell from the first step.
Faults: The ac02 taper and the depressed top are the two things only this check covers. Replacing ac02 by the linear taper, an easy substitution when a taper table is refactored, changes the eddy transport wherever the slope approaches GM_maxSlope, which in this weakly stratified 60 m mixed layer is most of the top three levels: an O(1) difference in the bolus velocity there and parts in 1e-2 in T and S within a day. A ten percent error in GM_background_K changes the slumping rate by ten percent and the tracers by parts in 1e-3. Ignoring the surface hFac from top_bump.bin, that is treating the depressed cells as full cells, changes Eta and the surface pressure by parts in 1e-2 immediately and the whole velocity field soon after. Because salinity is a passive dye carried only by the eddy transport and the Redi tensor, a fault in either shows in S at parts in 1e-2 with much less signal in T. A single-precision tensor leaves relative errors near 1e-7 in both tracers.

## Evidence

The overlay supplies its own data, data.pkg, data.gmredi, data.diagnostics and all four binaries it needs, t_ini.bin, s_ini.bin, u_ini.bin, topo_slp.bin and top_bump.bin, so no prepare_run and no links are required; input/eedata is used unchanged and the primary deck's Z-coordinate binaries, dy.bin (delY is set explicitly), the matlab generator, data.mpi and eedata.mth are dropped. debugLevel=3 makes this the most verbose log in the module but changes no answer. Streams 1 (surfDiag) and 3 (oceDiag) of the overlay's data.diagnostics are at -86400 s and fire exactly at 24 steps; stream 2 and the unnamed stream 4 stay silent. hMixCriteria=1.5 selects method 2 of model/src/calc_oce_mxlayer.F, which finds the depth where the local stratification exceeds the mean stratification above by that factor and then interpolates, so MXLDEPTH is still a continuous function of the state. topoFile makes the surface hFac less than one over the bump; hFacMin=0.05 applies. No MNC, no pickup, no cg3d. All binaries are real*8 and the deck sets readBinaryPrec=64 and writeBinaryPrec=64. This deck sets neither globalFiles nor useSingleCpuIO, so MITgcm's mdsio writes one file per tile and names the final dump <field>.<iteration>.001.001.data (pkg/mdsio/mdsio_write_field.F, the 'Case of 1 file per tile' branch), which the generator's collector and validate.py, both of which match ^<field>.<10 digits>.data$, would not see at all; the extra edit useSingleCpuIO=.TRUE. makes mdsio gather the tiles and write one global file per field, exactly as every sea-ice check's deck does. It is a pure I/O switch and changes no arithmetic; globalFiles=.TRUE. would do the same job for the non-exch2 decks, but useSingleCpuIO is the variant the finished task already exercises.

Floor: self-validation measures it on every run from `run.sh altbuild`, the same source under genmake2 -ieee, graded against the nominal run with this check's validate.py, and records it in the rubric's evidence (floor, altbuild); that in-image number is the floor a reviewer reads. The native measurement of 2026-09-02 between the same two builds on the x86_64 host: the optimised gfortran build and the IEEE -O0 build differ on this deck by at most 0.0e+00 in absolute terms, 0.0e+00 of the bound (in no field); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 2.9e+07 of the bound (FAIL), and the variant parameter off by five percent 1.9e+05 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.1 s natively.
