# ideal-2d-oce-geom

Upstream test: `code/mitgcm/verification/ideal_2D_oce/input.geom`. Policy: `pointwise`.

## The test

GEOMETRIC energetically-constrained eddy closure in the same 2-D ocean. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/ideal_2D_oce with the input.geom overlay, which changes only data.gmredi and data.diagnostics: the same 1x56x15 idealised zonally averaged global ocean restarted from the same pre-c54 pickup at iteration 36000, the same wind and surface-temperature relaxation, the same three time steps, the same CD scheme, the same seventh-order flux-limited advection, the same frozen salinity and the same ivdc_kappa=100, but the eddy transfer coefficient now comes from the GEOMETRIC closure compiled in through GM_GEOM_VARIABLE_K in the experiment's GMREDI_OPTIONS.h and switched on with GM_useGEOM=.TRUE.: a prognostic depth-integrated eddy kinetic energy is stepped forward with a generation term from the eddy flux, a linear dissipation at GEOM_lmbda=1.16e-7 per second (a hundred-day timescale), horizontal diffusion at GEOM_diffKh_EKE=500 and an advective and a westward wave-propagation term, and the coefficient is GEOM_alpha=0.08 times that energy divided by the depth-integrated Eady growth rate, bounded between GEOM_minval_K=50 and GEOM_maxval_K=2e4 and given a vertical structure function (GEOM_vert_struc=.TRUE.); the Visbeck coefficient is not set in this overlay and therefore defaults to zero, so this deck and the primary one exercise genuinely different production paths; the eddy energy starts uniform at GEOM_ini_EKE=10 because there is no pickup_gmredi file to restart it from (pkg/gmredi/gmredi_read_pickup.F says so in the log and pkg/gmredi/gmredi_init_varia.F sets it); the window is 10 steps of 86400 s, ten days, half the upstream twenty, chosen so that the overlay's 864000 s oceDiag average with GM_GEOMK and GEOMstru closes exactly on the final iteration and is graded. The -864000 s surfDiag snapshot with the six GEOM energy diagnostics is not graded: pkg/diagnostics/diagnostics_write.F evaluates a snapshot stream at myTime - deltaTClock and writes it under an earlier iteration's suffix (measured natively on 2026-09-05: an 11-step run writes surfDiag.0000036005 and oceDiag.0000036010 against a final state at 36011, so lengthening the window would grade neither), and no window makes it carry the final iteration..

The production path it forces: pkg/gmredi/gmredi_calc_geom.F, which forms the Eady growth rate and the first baroclinic mode speed, builds the two-dimensional GEOMETRIC coefficient, extends it in the vertical with the structure function and then steps the eddy-energy equation with its generation, dissipation, advection, wave and Laplacian terms, feeding pkg/gmredi/gmredi_calc_tensor.F and gmredi_calc_psi_bolus.F and the transports of gmredi_xtransport.F, gmredi_ytransport.F and gmredi_rtransport.F; the rest of the step is the same seventh-order advection, CD-scheme momentum, model/src/calc_ivdc.F and model/src/impldiff.F as the primary deck..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 10, the graded
value; the upstream deck runs 20 steps of 86400 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`, the input.geom/ overlay),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useSingleCpuIO=.TRUE.` in `data`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `GEOM_alpha=0.08000000000000003` in `data.gmredi` instead of 0.08:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

`run.sh altbuild` runs `ic/nominal` on an alternative build of the same source, `genmake2 -ieee` (gfortran -O0
-ffloat-store, strict IEEE arithmetic) instead of the optimised optfile; grading never uses it, self-validation measures the
check's floor between two legitimate builds from it.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of the final state dump plus the oceDiag average that closes on the final iteration, which carries the GEOMETRIC coefficient GM_GEOMK and its vertical structure GEOMstru; the eddy energy, its five tendency terms and the first mode speed live in the surfDiag snapshot, which is not graded, so they are seen through the coefficient they produce and the tracers it moves. The relative bound with an absolute floor is physical because the closure has a genuine equilibrium in which generation, dissipation and transport balance, so the coefficient it returns is fixed by GEOM_alpha, GEOM_lmbda and the resolved buoyancy field, and every fault above moves it by parts in a hundred or more. It is achievable for the same reasons as the primary deck: the domain is two-dimensional in latitude and depth so baroclinic instability cannot be resolved, the experiment's CPP_EEOPTIONS.h defines CG2D_SINGLECPU_SUM so the barotropic global sum is done in a fixed order on one processor, the upstream log records the solver converging in exactly 27 iterations at every step, and the flux limiter of the advection scheme is continuous. The extra amplification relative to the Visbeck deck is the prognostic energy, which remembers a perturbation instead of re-diagnosing it; ten days is under one dissipation timescale of a hundred days, so the memory is real but the damping has barely acted, and this is the argument that most needs a measurement to confirm. The switch that made an earlier survey want to exclude this experiment is ivdc_kappa=100 combined with deltaTtracer=86400: model/src/calc_ivdc.F sets a cell's vertical diffusivity to 100 m2/s wherever a strict sign test on the vertical density gradient says the column is unstable, and 1e-5 otherwise, so a flipped cell changes its diffusivity by seven orders of magnitude for a whole simulated day. On closer reading that switch is far less dangerous here than it looks, and the reason is worth stating precisely. This deck sets sBeta=0 and saltStepping=.FALSE., so density is a function of temperature alone and temperature is the only tracer the jumping diffusivity acts on. The implicit vertical flux it produces is proportional to the very temperature gradient whose sign decides the switch, so at the switching point the extra flux is zero: the tendency is continuous across the branch even though the coefficient is not, and a cell that flips under a two-ulp perturbation gains a flux of order the perturbation rather than of order 100 times the background. That is the opposite of the situation in the MLAdjust decks, where salinity is stepped as a passive spice tracer and can carry a finite vertical gradient across a neutral temperature interface. The window is nevertheless halved relative to the upstream twenty steps, to ten days, because the argument bounds the size of the jump and not its accumulation, and because a run restarted at equilibrium spends its time near neutrality in the convecting high latitudes. A native scan of the worst relative spread against window length at 1, 2, 5, 10 and 20 steps must be run before the bound is fixed: smooth growth means ten steps is comfortable, isolated cells with O(1) differences would mean the argument above is wrong somewhere and the window must go to five steps or fewer, at the cost of the two diagnostics files. The variant perturbs GEOM_alpha, which the overlay writes explicitly and which multiplies the eddy energy in every water column from the first step, when the energy is still at its uniform initial value of 10. The one way it could be blinded is the lower bound GEOM_minval_K=50: if the coefficient sits on that floor everywhere, GEOM_alpha has no effect at all and the measured spread would be exactly zero. The fallback in that case is GEOM_lmbda=1.16e-7, which enters the energy equation itself and is therefore upstream of every clamp, and after that GM_background_K=10, which the overlay also sets and which is added to the coefficient in every wet cell.
Faults: GEOMETRIC carries a prognostic variable, so an error compounds instead of being re-diagnosed each step, and the coefficient it produces is graded directly through oceDiag. A ten percent error in the dissipation rate GEOM_lmbda changes the equilibrium eddy energy by ten percent within a few dissipation times and the graded GM_GEOMK field by parts in 1e-1 well inside ten days. Dropping the generation term, which is the eddy flux acting on the mean buoyancy gradient, leaves the energy decaying exponentially from its uniform initial value, and GM_GEOMK with it: an O(1) difference. Dropping the westward wave-propagation term changes the meridional distribution of the energy, and of GM_GEOMK, by tens of percent at mid latitudes. Omitting the vertical structure function makes the coefficient depth-independent and changes GEOMstru by O(1) and the residual overturning by parts in 1e-2. A ten percent error in GEOM_alpha changes the coefficient by ten percent everywhere it is not clamped and the temperature field by parts in 1e-3. A single-precision energy equation leaves relative errors near 1e-7 in the graded energy after ten steps.

## Evidence

The overlay supplies only data.gmredi and data.diagnostics; data, data.pkg, eedata, the pickups and the three input binaries all come from input/, so the same pickup handling as the primary check applies: pickup.0000036000 and pickup_cd.0000036000 carry no .data suffix and pkg/mdsio/mdsio_read_field.F finds them under the plain name, usePickupBeforeC54 and pickupStrictlyMatch=.FALSE. must stay, and the final dump is written at iteration 36010. There is no pickup_gmredi file, so pkg/gmredi/gmredi_read_pickup.F prints a warning and restarts with a uniform GEOM_EKE=GEOM_ini_EKE; that is the upstream behaviour and must not be fixed. useMNC is not set. Of the overlay's four diagnostics streams, surfDiag (-864000 s, ETAN, DETADT2 and the six GEOM energy fields on level 1) and oceDiag (864000 s, DRHODR, RHOAnoma, GM_GEOMK, GEOMstru and the tensor components on levels 2 to 13) close exactly at ten steps and are graded; streams 2 and 4 have had their fileName commented out and are at 1728000 s, twenty steps, so they stay silent, and that is a second reason not to lengthen the window to twenty steps without first checking what pkg/diagnostics does with a blank output-stream name. The per-level statistics stream writes plain text with diagSt_mnc=.FALSE. and is not collected. GM_Visbeck_alpha is absent from this overlay and therefore zero, so the Visbeck branch of gmredi_calc_tensor.F is skipped entirely. readBinaryPrec=64, real*8 inputs, saltStepping off. This deck sets neither globalFiles nor useSingleCpuIO, so MITgcm's mdsio writes one file per tile and names the final dump <field>.<iteration>.001.001.data (pkg/mdsio/mdsio_write_field.F, the 'Case of 1 file per tile' branch), which the generator's collector and validate.py, both of which match ^<field>.<10 digits>.data$, would not see at all; the extra edit useSingleCpuIO=.TRUE. makes mdsio gather the tiles and write one global file per field, exactly as every sea-ice check's deck does. It is a pure I/O switch and changes no arithmetic; globalFiles=.TRUE. would do the same job for the non-exch2 decks, but useSingleCpuIO is the variant the finished task already exercises.

Floor: self-validation measures it on every run from `run.sh altbuild`, the same source under genmake2 -ieee, graded against the nominal run with this check's validate.py, and records it in the rubric's evidence (floor, altbuild); that in-image number is the floor a reviewer reads. The native measurement of 2026-09-02 between the same two builds on the x86_64 host: the optimised gfortran build and the IEEE -O0 build differ on this deck by at most 0.0e+00 in absolute terms, 0.0e+00 of the bound (in no field); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d W-unit target (the deck's active key; cg2dTargetResidual is commented out) loosened 1e10 to 7.0E-7 uses 2.5e+07 of the bound (FAIL, 8104 of 11200 values over), and loosened only 1e3 to 7.0E-14 uses 1.5 of the bound (FAIL, 4 of 11200), and the variant parameter off by five percent 5.3e+06 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.1 s natively.
