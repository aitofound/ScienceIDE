# front-relax-gmredi-fm07

Upstream test: `code/mitgcm/verification/front_relax/input.mxl`. Policy: `pointwise`.

## The test

GM skew flux with the fm07 transition-layer taper under a mixed layer. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/front_relax with the input.mxl overlay: the same 1x32x25 zonally symmetric y-z channel but on a much coarser and deeper grid (100 km in both horizontal directions, ten 20 m levels on top of fifteen stretched levels down to 2 km, flat bottom from topog.bin) representing a 200 m thick, exactly unstratified mixed layer sitting on a stratified warm bowl, started from t_ini.bin, s_ini.bin and a geostrophic u_ini.bin, with a linear equation of state, temperature as the only buoyancy-carrying tracer and salinity as a passive dye (sBeta=0), no surface forcing, f-plane at f0=1e-4, biharmonic lateral viscosity viscA4=12e5, linear bottom drag, and a vertical diffusivity profile diffKrNrT=diffKrNrS that is 1e-2 in the top six levels and 2e-5 below, so that the mixed layer stays mixed; pkg/gmredi runs in its default skew-flux form with GM_background_K=1000 setting both the GM and the Redi coefficient, GM_maxSlope=1e-2 and, the whole point of this deck, GM_taper_scheme='fm07', the Ferrari and McWilliams 2007 transition-layer scheme with GM_facTrL2dz=0 and the package defaults GM_facTrL2ML=5 and GM_maxTransLay=500 m, which needs a mixed-layer depth and therefore hMixCriteria=-0.1; cAdjFreq=-1 makes model/src/convective_adjustment.F run every step; the window is 24 steps of 3600 s, one day, one step less than the upstream 25. The overlay's -86400 s surfDiag snapshot stream (GM_hTrsL, GM_baseS, GM_rLamb, MXLDEPTH) is not graded: pkg/diagnostics/diagnostics_write.F evaluates a negative-frequency (snapshot) stream at myTime - deltaTClock and writes it during the following step under the previous iteration's suffix: measured natively on 2026-09-05, a 25-step run writes surfDiag.0000000024 while the final state dump carries iteration 25 (retained under comment/fault-probes), so no window makes a snapshot land on the final iteration and the snapshot streams are not graded; the check grades the state dump alone, and the taper is seen through the state it feeds..

The production path it forces: pkg/gmredi/gmredi_calc_tensor.F, which for fm07 calls pkg/gmredi/gmredi_slope_limit.F three times per level (once for the tensor and once for each horizontal flux component) to build the slope magnitude and direction, locate the base of the transition layer and evaluate the two tapering functions G and G-hat, followed by the tensor application in gmredi_xtransport.F, gmredi_ytransport.F and gmredi_rtransport.F inside model/src/calc_gt.F and calc_gs.F; model/src/calc_oce_mxlayer.F supplies the mixed-layer depth every step and model/src/convective_adjustment.F with convective_weights.F and convectively_mixtracer.F runs its sort-and-mix sweep every step..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 24, the graded
value; the upstream deck runs 25 steps of 3600 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`, the input.mxl/ overlay),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useSingleCpuIO=.TRUE.` in `data`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `GM_background_K=1000.0000000000002` in `data.gmredi` instead of 1000:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

`run.sh altbuild` runs `ic/nominal` on an alternative build of the same source, `genmake2 -ieee` (gfortran -O0
-ffloat-store, strict IEEE arithmetic) instead of the optimised optfile; grading never uses it, self-validation measures the
check's floor between two legitimate builds from it.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|; inside `surfDiag` the records `GM_hTrsL`, `GM_baseS`, `GM_rLamb` are not graded (GM_hTrsL is the depth of the base of the fm07 transition layer, which pkg/gmredi/gmredi_slope_limit.F sets to a cell-interface depth -depthZ(k+1) rather than to an interpolated value, so it can only change by a whole level; GM_baseS and GM_rLamb are the slope and the inverse slope-gradient length stored at that same discrete interface and jump with it).
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of the final state dump, U, V, W, T, S, Eta, PH and PHL, plus the surface-diagnostics snapshot the -86400 s stream writes at the final iteration, compared relatively with an absolute floor. The bound is physical because with no forcing and no resolved eddies the evolution over one day is a deterministic functional of the tensor and of the taper: the mixed layer, the transition layer and the stratified interior each get a prescribed slope treatment and every fault above displaces the result by parts in a hundred or worse. It is achievable in the sense that the deterministic parts of the step are clean: the barotropic solve is set to cg2dTargetResidual=1e-13 on a 32-point domain so its iteration count is very unlikely to move, the flow is two-dimensional in y and z so baroclinic instability cannot grow, and every tensor and tridiagonal evaluation is fixed-length direct arithmetic. Two discrete mechanisms nevertheless exist and both are handled rather than ignored. The first is fm07 itself: gmredi_slope_limit.F sets the base of the transition layer to a cell-interface depth, hTransLay = -depthZ(k+1), the first time a criterion on the accumulated slope is met, so the transition-layer depth and the baseSlope and recipLambda stored with it are level-quantised and can only move in whole levels. That stream is not graded at all (its snapshot never carries the final iteration, see the configuration), so those three level-quantised diagnostics never enter the comparison; the taper they parameterise is fully graded through the prognostic state, and if a level ever does flip, the state itself will show it, which is the honest outcome rather than a hidden one. The one hazard this family of decks carries, and the reason the earlier survey wanted to exclude them, is cAdjFreq=-1: model/src/convective_adjustment.F runs every step and model/src/convective_weights.F decides cell by cell, on the strict sign test (rho(k)-rho(k-1))*rkSign*gravitySign < 0, whether to replace two adjacent cells by their volume-weighted mean. That is a discrete switch, but in this configuration its effect is very nearly continuous, and that is what makes the check defensible. Salinity is a passive dye with sBeta=0, so density is a function of temperature alone; the switch therefore fires exactly when the temperature difference across the interface changes sign, and at that moment mixing the two cells changes their temperature by half of a difference that is itself zero, so the temperature tendency is continuous across the switch. The only quantity that could jump is salinity, whose vertical gradient is not tied to the criterion; but the initial salinity field of this experiment is exactly uniform in the vertical (it varies with y only), so at the start mixing salinity is an exact no-operation, and the vertical salinity gradients that develop later are small. A perturbed run can therefore flip a marginal interface and the resulting difference is bounded by the local tracer jump rather than by anything O(1). This is an argument, not a measurement, and it is why the window is kept at or below the deck's own step count and why a native scan of the worst relative spread against window length at 6, 12, 24, 48 and 96 steps must be run before the bound is fixed: smooth growth means the window can stay or grow, isolated cells with O(1) differences mean the convective switch is flipping on a real salinity jump and the window must be shortened and the check flagged chaotic. The variant perturbs GM_background_K, which the deck writes explicitly and which sets both the GM and the Redi coefficient, so it enters the tendency of both tracers in every wet cell from the first step; that is the same parameter as the primary front_relax check, which the addendum explicitly permits and which keeps the family comparable.
Faults: This is the only check in the suite that exercises a transition-layer taper, so it is where a fault in that machinery shows. Falling back to no tapering, that is using the raw slope inside the mixed layer where fm07 would cut it in linearly, makes the skew flux blow up in the top ten levels where the isopycnals are nearly vertical, an O(1) difference in T and S there. Getting the sign of the D-over-lambda term of the tapering function wrong in gmredi_slope_limit.F flips the sense of the transition and changes the near-surface eddy flux by tens of percent, parts in 1e-1 of the temperature field within a day. A ten percent error in GM_background_K changes the slumping rate by ten percent and the tracers by parts in 1e-3 in the same window. Omitting the MAX that keeps the transition layer at least as thick as the local cell (minTransLay) collapses it onto a single level and changes GM_hTrsL by a whole level, which is seen through the near-surface tracers the taper feeds. Because salinity is a passive dye that only the tensor moves, a fault in the isopycnal as opposed to the skew part shows in S at parts in 1e-2 while leaving T much less disturbed. A single-precision tensor leaves relative errors near 1e-7 in both tracers.

## Evidence

The overlay supplies its own data, data.pkg, data.gmredi, data.diagnostics and its own binaries t_ini.bin, s_ini.bin, u_ini.bin and topog.bin; topo_slp.bin lives in the same directory but is the sloping bottom used by the bvp set-up and is not read here, so it is dropped, as are the primary deck's Z-coordinate binaries, dy.bin (this deck sets delY explicitly), the matlab generator, data.mpi and eedata.mth. There is no eedata in the overlay, so input/eedata is used, and it sets nothing. No MNC, no pickup, no prepare_run, no cg3d. Of the overlay's four diagnostics streams only stream 1, surfDiag at -86400 s, fires inside a 24-step window; streams 2 and 4 have no fileName at all and their frequencies (-864000 s and 1728000 s) keep them silent, which is fortunate and is a reason not to lengthen the window past 240 steps without checking what pkg/diagnostics does with a blank stream name. The per-level statistics stream at stat_freq=3600 writes plain text files every step, which are not collected but do fill the run directory with two dozen small files. hFacMin=0.1 and the deck's ten dead-ish deep levels are inherited from the shared SIZE.h with Nr=25. All binaries are real*8 and the deck sets readBinaryPrec=64 and writeBinaryPrec=64. This deck sets neither globalFiles nor useSingleCpuIO, so MITgcm's mdsio writes one file per tile and names the final dump <field>.<iteration>.001.001.data (pkg/mdsio/mdsio_write_field.F, the 'Case of 1 file per tile' branch), which the generator's collector and validate.py, both of which match ^<field>.<10 digits>.data$, would not see at all; the extra edit useSingleCpuIO=.TRUE. makes mdsio gather the tiles and write one global file per field, exactly as every sea-ice check's deck does. It is a pure I/O switch and changes no arithmetic; globalFiles=.TRUE. would do the same job for the non-exch2 decks, but useSingleCpuIO is the variant the finished task already exercises.

Floor: self-validation measures it on every run from `run.sh altbuild`, the same source under genmake2 -ieee, graded against the nominal run with this check's validate.py, and records it in the rubric's evidence (floor, altbuild); that in-image number is the floor a reviewer reads. The native measurement of 2026-09-02 between the same two builds on the x86_64 host: the optimised gfortran build and the IEEE -O0 build differ on this deck by at most 0.0e+00 in absolute terms, 0.0e+00 of the bound (in no field); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 1.1e+06 of the bound (FAIL), and the variant parameter off by five percent 2.0e+05 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.1 s natively.
